# `frc.robot` — Robot Project Guide

The example robot that consumes `frc.lib`. It doubles as the integration test bed for the library,
so keep it buildable and runnable in simulation. Read the root [AGENTS.md](../../../../../AGENTS.md)
first, and [frc/lib/AGENTS.md](../lib/AGENTS.md) if the change needs a new IO or device.

## Top-level files

| File | Role |
| --- | --- |
| `Robot.java` | `LoggedRobot`: AdvantageKit setup per mode, scheduler loop, sim battery update. Keep logic out of here. |
| `RobotContainer.java` | Creates subsystems via their factories, binds controls, builds the auto chooser. |
| `RobotState.java` | Singleton (`RobotState.getInstance()`) for shared state: pose estimate, velocities. |
| `Constants.java` | Global mode (`currentMode`, `simMode`), `tuningMode`, robot dimensions. |
| `Ports.java` | **Every** CAN / DIO / PWM assignment, as `Device.CAN` / `Device.DIO` / `Device.PWM`. |
| `FieldConstants.java` | Field geometry and AprilTag layout selection. |
| `BuildConstants.java` | Generated by gversion — never edit. |

## Adding a subsystem

Create `subsystems/<name>/` (lowercase package) with two files:

### `<Name>Constants.java` — configuration and factory

```java
@NoArgsConstructor(access = AccessLevel.PRIVATE)
public class IntakeConstants {
    public static final String NAME = "Intake";

    private static final Current SUPPLY_LIMIT = Amps.of(40.0);
    // ... gear ratios, PID, characteristics, vendor configs

    /**
     * Creates the Intake subsystem with IO implementations for the current robot mode.
     *
     * @return the configured Intake subsystem
     */
    public static Intake get() {
        return switch (Constants.currentMode) {
            case REAL -> new Intake(new MotorIOTalonFX(NAME, config(), Ports.intake));
            case SIM -> new Intake(new MotorIOTalonFXSim(NAME, config(), Ports.intake));
            case REPLAY -> new Intake(new MotorIO() {});
        };
    }
}
```

- All tunable numbers, vendor configuration objects, and physical characteristics for the
  subsystem live here as `static final` constants with units.
- The factory is the **only** place that chooses an IO implementation. It handles all three modes;
  `REPLAY` always uses anonymous no-op IOs (`new MotorIO() {}`).
- Name it `get()` when it returns the subsystem (`DriveConstants.get()`, `LaserCAN1Constants.get()`);
  `create()` is used when the factory registers itself instead of returning (`VisionConstants`).
- Port numbers come from `Ports`, never literals here.

### `<Name>.java` — the subsystem

- `extends SubsystemBase`. Constructor takes **IO interfaces** (or a `Mechanism` / device built from
  them) — never vendor classes, never `Constants.currentMode` checks.
- Holds devices/mechanisms (`DistanceSensor`, `RotaryMechanism`, ...) and calls each one's
  `periodic()` from its own `periodic()`. If it owns an IO directly, it owns the
  `<Thing>InputsAutoLogged` and calls `io.updateInputs` + `Logger.processInputs(NAME, inputs)`.
- Exposes behavior as **command factory methods** (`public Command intake()`, built with
  `run`, `runOnce`, `startEnd`, `Commands.sequence`, ...) and state as `Trigger`s / getters.
  Bind them in `RobotContainer`; don't schedule commands from inside a subsystem.
- Shared robot-wide state (pose, velocity) goes through `RobotState.getInstance()`, not through
  references to other subsystems.
- Log derived values with `Logger.recordOutput(NAME + "/Key", value)`.

`subsystems/drive/` is the full-featured reference (multiple IOs, odometry thread, sim modules);
`subsystems/lasercan1/` is the minimal one (a single device wrapper).

### Wire it up

1. Add its ports to `Ports.java` (unique CAN ID per bus, 1–63; `Device.CAN` throws on conflicts).
2. In `RobotContainer`, create it with `<Name>Constants.get()` and bind controls in
   `configureButtonBindings()` using `controller` (`CommandXboxControllerExtended`).
3. Run `./gradlew simulateJava` and confirm it constructs and logs in SIM.

## Commands and autos

- Reusable robot commands go in `commands/` as either a class (`DriveToPose`, with fluent
  `withTolerance(...)` setters) or static factories (`DriveCommands.joystickDrive(...)`).
- Autonomous routines are methods on `autos/AutoFactory` returning an `frc.lib.autos.Auto`
  (name, command, display poses). Register them in `RobotContainer`'s `autoChooser`.
- Use `LoggedDashboardChooser` for dashboard choices so selections are logged and replayable.

## Mode handling

`Constants.currentMode` is `REAL` on a roboRIO and `Constants.simMode` (`SIM` or `REPLAY`) on a
desktop. Code outside factories and `Robot.java` should not branch on mode — that's what the IO
layer is for. If you think you need a mode check in a subsystem, add a method to the IO interface
instead.
